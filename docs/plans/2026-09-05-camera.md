# ChatGPT Camera Implementation Plan

**Goal:** Build an Android camera APK and Windows receiver that attach captured photos to the foreground Codex composer without sending a message.

**Architecture:** Paired Android client sends a capture reservation, then JPEG bytes over certificate-pinned HTTPS to a Windows tray application. The receiver records the foreground window, composer and session identity; it attaches only if these still match. Uncertain targets or attachment outcomes remain in a durable queue for user review.

**Tech Stack:** Android Java / Camera2 / ZXing, .NET 8 Windows Forms / Kestrel / UI Automation, QRCoder.

The user confirmed requirements and the recommended design, authorizing implementation in this task. No repository or branch existed. Work proceeds locally without further execution-mode approval.

## Task 1 — Core safety and transfer state
Create `windows/CameraReceiver/Core.cs` and `windows/CoreTests/Program.cs`.
First execute failing assertions for different windows, different sessions, expired captures, unknown composer, duplicate uploads, and restart recovery. Implement immutable target identity and durable capture records. Run `dotnet run --project windows/CoreTests`.

## Task 2 — Windows receiver
Create `windows/CameraReceiver/Program.cs`, `ReceiverServer.cs`, `DesktopTarget.cs`, `MainForm.cs` and project files. Use authenticated pinned HTTPS, bounded JPEG uploads, persisted queue, QR pairing, explicit receipt/attachment statuses. Inspect installed application code for attachment behavior. Compile and run local HTTPS integration tests; test wrong token, oversized/invalid image, retry and conflict behavior.

## Task 3 — Android camera
Create `android/app/src/main/java/local/chatgpt/camera/` with activity, camera controller and transport. Add manifest, resources and Gradle configuration. Include in-app preview, shutter, QR scanning, certificate pinning, persistent pending upload and retry. Test pairing parsing and transport against the receiver, compile APK and verify signature.

## Task 4 — Packaging and evidence
Create a self-contained Windows build, signed debug APK for personal installation, source archive, Chinese installation instructions, and verification report. Test available components and explicitly record absent hardware or inaccessible desktop verification. Do not report automatic attachment as verified without observing the attachment.
