# ChatGPT 相机：第一版设计草案

状态：用户已确认需求与技术设计。0.1.0 测试版已实现；构建与协议测试通过，真实安卓相机及 Codex 附件自动插入尚待实机验收。

## 已确认需求

- 安卓手机拍摄后自动传输照片。
- 接收目标是拍照时用户正在打开的 Windows Codex 界面。
- 照片应成为该界面输入框中的附件，消息由用户手动发送。
- 第一版面向个人、同一 Wi-Fi 下的一台手机与一台电脑；电脑可以运行接收程序。
- 配对设备间传输，失败保留照片并允许重试；正常网络下争取数秒内完成。

## 推荐方案

安卓相机与 Windows 托盘接收程序配合。首次通过二维码完成设备配对，保存设备身份并使用加密连接。按下快门时手机先发起接收请求，电脑记录当时前台 Codex 窗口及能识别到的会话标识，然后接收照片并尝试通过桌面辅助功能定位输入框、使用系统图片粘贴能力附加图片。仅当前台窗口与会话仍符合记录时执行附加操作。

手机请求抵达电脑与实际按下快门存在网络时差；不能承诺精确到同一毫秒。优先定义为电脑收到拍摄请求时的活动界面。

如果前台不是 Codex、会话已切换、输入框不可定位，或不能可靠识别会话，则将照片留在接收队列，提示用户回到目标界面后手动点击插入。不得盲目向其他窗口粘贴。插入动作与附件成功出现分别记录；无法确认附件出现时不得报告插入成功。

## 替代方案

1. 只接收并复制图片，由用户按 Ctrl+V：稳定性更容易控制，但不满足自动附加体验，可作为备用路径。
2. 通过内部调试接口写入草稿：可能更直接，但依赖未确认的接口和桌面版本，不作为第一版基础。

## 验证与实施顺序

1. 先做 Windows 最小验证：确认当前版本能定位窗口、识别会话、将测试图片附加到草稿且不发送消息。
2. 验证切换窗口、切换会话、多个窗口、输入框失焦时不会误投。
3. 接入安卓拍摄、加密配对、传输状态、重试与重复上传去重。
4. 联调真实安卓手机与 Windows，测量拍摄到附件显示的延迟。
5. 提供 APK、Windows 接收端、源码与安装说明；明确未通过实机验证的部分。

## 决策记录

- 接收产品以截图和用户补充为准：Codex Windows 桌面端。
- 接收对象为拍摄时活动界面，而非配置中的固定会话。
- 仅添加附件，不自动发送消息。
- 推荐本地配对接收端，避免依赖尚未确认的公开草稿接口。
- 自动附加的可靠性尚未验证；桌面端技术验证先于完整安卓开发。

## 实机验收项

用户已接受目标界面变化或无法可靠识别时保留图片并提示手动插入。仍需在真实手机与当前 Codex 版本上确认相机预览、扫码、拍摄方向、传输延迟、会话识别及附件出现。测试版在无法识别会话时会进入保留队列，不能因此视为自动附加验收通过。
